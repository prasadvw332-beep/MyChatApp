# Changelog

What changed, newest first, grouped by day. Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).
The commit and pull request of each change explain the *why* in detail (`git log`, or the PR list on GitHub).

## Unreleased

Work on feature branches, waiting for review and merge into `main` (in this order):

### Added
- **Autoscaling**: HorizontalPodAutoscalers for the backend (2-6), ingestion workers (2-8) and frontend (2-4)
  on CPU, with scale-down stabilization; PodDisruptionBudgets; the Deployments no longer set `replicas`
  (the HPAs own it). Docker Desktop needs the metrics-server (`deploy/README.md`, "Autoscaling").
  `feature/autoscaling`
- **User feedback**: thumbs up/down under every answer, with an optional "what was wrong?" on a thumbs down;
  stored in PostgreSQL (`feedback`, migration 0007) with a copy of the question, answer, sources and the
  answer's request id (to find its logs and trace); the rating stays on the saved message;
  `answer_feedback_total` metric. `feature/user-feedback`
- **Rate limiting**: per-user limits on the endpoints that run a model or embed documents (chat + agent,
  titles, uploads, eval runs) and per-IP on registration; fixed windows counted in PostgreSQL
  (`rate_limits`, migration 0006) so every replica shares them; `429` with `Retry-After` in the usual
  error shape; audited and counted (`rate_limit_rejections_total`); fails open if PostgreSQL is down.
  `feature/rate-limiting`
- **Production dashboard**: the Grafana dashboard reworked into an end-to-end operations view: alarms and
  per-component health, SLOs with error budget and burn rate, ingest queue from PostgreSQL, PostgreSQL / Qdrant /
  MinIO / Ollama panels, the telemetry pipeline, alert and restart annotations; a live system map
  (Canvas, animated flow), latency heatmaps, SLO gauges, donuts, 10 s live refresh; synthetic users
  (`deploy/loadgen`, compose profile `demo`) so the dashboard has traffic to show. Prometheus alert rules
  (`alerts.yml`), postgres-exporter, and scraping of Qdrant, MinIO, the Collector, Tempo and Grafana.
  `feature/production-dashboard`
- **Caching**: embeddings cached by text (memory, then PostgreSQL `embedding_cache`, shared by the
  backend and workers); a semantic answer cache in Qdrant answers a chat's first question from a stored
  answer to a similar one (cosine >= 0.95), emptied on every document change; `X-Cache` header, "Caching"
  row in Grafana. `feature/caching`
- **Agent mode** with MCP: the knowledge base exposed as an MCP server, and an agent that picks tools
  (search, list, read documents) before answering. `feature/agent-mcp`
- **Observability**: Prometheus metrics (requests, latency, LLM time to first token, retrieval, ingestion),
  OpenTelemetry traces through a Collector to Tempo, Grafana with a provisioned dashboard; trace ids on
  every log line. `feature/observability`
- **LLM token and cost tracking**: tokens per call (chat, agent, title), cost at configurable prices,
  generation speed; per-user usage in PostgreSQL (`llm_usage`), "Tokens & cost" in Grafana.
  `feature/llm-usage-tracking`
- **Guardrails**: prompt-injection checks on the question, on retrieved chunks (shared by all users) and
  on agent tool results; chunks fenced as data in the prompt; a canary marker that withholds an answer
  leaking the system prompt; optional Llama Guard content safety (`GUARD_MODEL`); `monitor` mode;
  "Guardrails" row in Grafana. `feature/guardrails`
- Frontend **ESLint** and **tests** (Vitest + jsdom, including a smoke test of the whole app). `refactor/frontend-modules`
- **Repository tooling**: Makefile, pre-commit hooks, `.editorconfig`, `.gitattributes`, this changelog.
  `chore/repo-hygiene`

### Changed
- **Agent on LangGraph**: the agent loop is now a `StateGraph` (agent and tools nodes); same events,
  same behaviour. `feature/langgraph-agent`
- Grafana dashboard is generated by `build_dashboard.py`; CI fails if the JSON is edited by hand.
  `chore/dashboard-generator`
- Backend folders: `clients/` (Ollama, MinIO, Qdrant), `repositories/` (PostgreSQL), `services/`
  (business logic), request bodies in `schemas/`; tests split into `unit/` and `api/` with shared
  fixtures. No behaviour change. `refactor/backend-structure`
- Frontend split from one 908-line `main.js` into `api.js`, `state.js` and one module per part of the
  screen (`features/`). No behaviour change. `refactor/frontend-modules`
- Kubernetes: `deploy/k8s/base` + `overlays/dev` and `overlays/prod`, replacing CI's `sed` edits.
  `chore/k8s-overlays`

### Fixed
- 502 errors after the backend container restarted: nginx now re-resolves the backend's address.
  `fix/nginx-backend-dns`

## 2026-10-31

### Added
- Login (accounts, session cookie, login throttling); chats and documents belong to a user
- Batch ingestion: queue in PostgreSQL, worker processes, retries, CLI and HTTP API
- Database migrations (Alembic), run safely by every replica at startup
- Docker images, docker-compose, Kubernetes manifests, CI/CD to ghcr.io and EKS
- Production hardening: one error format without leaked internals, request ids, liveness/readiness
  checks, timeouts on every external call, refusal to start with insecure settings
- Audit log (who did what), user id on log lines, secret redaction in logs

### Changed
- Backend refactored toward SOLID: a `VectorStore` interface, smaller ingestion steps

## 2026-10-23

- First version: local RAG chatbot. FastAPI + LangChain backend with Ollama and Qdrant, Vite frontend
- RAGAS evaluation of answer quality
- PostgreSQL for chat history, document metadata and evaluation results
